How It All Works
The universal architecture shared by every escape room

Every escape room in the suite (and the EOY student template) shares the same fundamental architecture. Once you understand one, you understand all of them. The structure has three layers:

1
CSS Design System (:root variables)

All colors, glows, and spacing are defined once as CSS custom properties. Changing the theme means changing a handful of hex values at the top. Green escape room, purple escape room, CyberPunk template — all just different :root values.

2
HTML Screen System (4 screens, only one visible at a time)

The page contains four <div class="screen"> blocks — Splash, Codename, Question, and Results. JavaScript shows/hides them by toggling the .active CSS class. Only the active screen is displayed; the rest are display: none.

3
JavaScript Data + Logic

Two data objects drive everything: CONFIG (title, teacher name, storage key) and QUESTIONS (the array of room objects). A let S = {...} state object tracks progress, and a set of functions handle each interaction: pick, skip, reset, save, load.

📁
Important: Why No External Dependencies?

These files use fetch()-free design because browsers block network requests when files are opened via file:// protocol (a security restriction). All logic is embedded. The only exception is loading the Google Fonts stylesheet — which requires an internet connection for the fonts but degrades gracefully to monospace if offline.

JS://BUILD

JS://BUILD is the only tool in the suite where students actually write code. Over 25 levels, they incrementally build a complete, working Number Guessing Game in JavaScript — starting with a single console.log() and ending with a fully interactive browser game they can download and keep.

Interface Features

  • Split-panel: instructions left, code editor right
  • Line-numbered editor with Tab key support

The Payoff Moment

At Level 25, students click a "Download My Game" button that creates a real .html file using the Blob API and saves it to their computer. They've built a game they can show their parents. That moment of genuine ownership is the entire point.

CT Problem Solver
Offline AI-Style CT Breakdown Tool

The CT Problem Solver was designed to help students apply computational thinking to problems across all five core subjects. Students type or paste a problem, select their subject, and the tool generates a four-pillar CT breakdown with action steps and examples.

⚠️
Important Build Decision: Why Offline?

The original version called the Anthropic API directly. When opened via file:// protocol, browsers block fetch() requests — a security rule called CORS/Mixed Content blocking. The rebuild replaced the API call with a keyword-aware embedded knowledge base containing subject-specific and concept-specific CT breakdowns. No internet needed, no API key needed, works instantly anywhere.

Subject Coverage

  • Math — word problems, geometry, fractions, equations
  • ELA — reading comprehension, essays, grammar, stories
  • Science — experiments, classification, data, hypotheses
  • Social Studies — history, geography, government, economics
  • Computer Science — algorithms, debugging, data, programs
EOY SUCCESSFUL GUIDE
End-of-Year Culminating Activity · CyberPunk Style · 2025–2026
📅 When: End of Year / End of Semester 🎯 Type: Student-Created Escape Room ❓ Questions: 20 per student 🌐 Delivery: Embedded in Google Site

The EOY Successful Guide is the culminating metacognition activity for the semester. Rather than playing an escape room, students now build one. They are given Mr. G's CyberPunk-styled template — a fully functional 20-question escape room game — and must fill in their own review questions and answers from the year's content.

1
Open the Template

Students receive the template from the Word document. The only section they touch is marked in orange font — the CONFIG object (title, subtitle, teacher name) and the QUESTIONS array (20 question objects).

2
Write 20 Questions

Students create 20 review questions from the year. Each question needs: a room name, question text, 2–4 choices, the index of the correct answer (0, 1, 2, or 3), and a hint.

3
Convert and Save as index.html

Students copy their completed code into a Text Editor, convert to plain text, uncheck the .txt box, and name the file index.html.

4
Embed in Google Site

The HTML file is embedded in the student's Google Site portfolio for Mr. G to observe and attempt. Other students can play each other's escape rooms.

Section 1 — The CONFIG Object

This object sets the title, subtitle, teacher name, subject line, and localStorage key for the game.

Student Configuration Zone — CONFIG JavaScript
const CONFIG = { title: "My 25-26 Review Application", // ← Change to your own title subtitle: "My Awesome Questions and Answers", // ← Your unit or topic teacher: "Mr. G", // ← Your teacher's name subject: "Blue Valley 229 | CS", // ← Course / school storageKey: "bv229_room_v1" // ← Change v1→v2 for a fresh start };
title Shows as the big title on the splash screen. Make it descriptive — this is what your classmates see first.
subtitle A shorter tagline under the title. Could be your class period, topic, or a fun mission name.
teacher Your teacher's name. Shows on the results page at the bottom.
subject Your school and course name. Also shows on the results page.
storageKey A unique name used to save progress in the browser. If two students use the same storageKey on the same computer, their progress will overwrite each other — change the number (v1→v2) to prevent this.

Section 2 — The QUESTIONS Array

Each of the 20 rooms needs one object in this array. Every object must have the same five fields.

One Question Object — Complete Structure JavaScript
{ room: "Boolean Bay", // Room name — shown as a badge in the game question: "Which of the following is a Boolean?", // The actual question choices: ["42", "\"true\"", "true", "[true]"], // 2–4 answer options answer: 2, // INDEX of correct choice (0=first, 1=second...) hint: "Boolean values are NOT in quotes. 🎯" // Shown after a wrong guess },
room A fun name for this challenge room. Shows in a badge above the question. Be creative!
question The question students must answer. Keep it clear and specific. Avoid trick wording.
choices An array of 2–4 answer options. Each option is a string in quotes. Square brackets hold the array, each choice is separated by a comma. The game auto-assigns A, B, C, D labels.
answer The INDEX (position) of the correct choice. Index starts at 0! So if the correct answer is the third option, answer is 2 — not 3.
hint A hint that appears after a wrong guess. Write it to guide thinking, not give away the answer directly. Emojis are encouraged!
⚠️ Most Common Student Mistakes
1. Wrong answer index. Students write answer: 3 meaning "the third choice" but JavaScript counts from 0 — the third choice is index 2.

2. Missing comma between question objects. Each { ... } object in the QUESTIONS array must end with a comma — except the very last one.

3. Unmatched quotes. If the question text contains an apostrophe (like "It's"), use double quotes to wrap the string: "It's a boolean" — not single quotes.

Code Education: CSS Design System
How the visual theme works — the :root variables

Every escape room opens with a :root block in the CSS. This is the "design system" — it defines every color, glow effect, and spacing value as a variable. Using variables instead of hard-coded colors means the entire visual theme can be changed by editing just this one block.

CyberPunk :root Design Tokens CSS
:root { /* ── Background Colors ── */ --bg: #060912; /* Page background — near-black with blue tint */ --bg-card: rgba(10, 22, 44, 0.97); /* Card/panel background */ --border: rgba(0, 220, 255, 0.18);/* Semi-transparent cyan border */ /* ── Accent Colors ── */ --cyan: #00dcff; /* Primary cyan — buttons, borders */ --cyan-hi: #70efff; /* High-brightness cyan — titles */ --amber: #ffb700; /* Warning/hint color — room badges */ --green: #00ff88; /* Correct answer / success */ --red: #ff3860; /* Wrong answer / danger */ /* ── Text Colors ── */ --text: #b8d0e8; /* Body text — light blue-gray */ --text-hi: #e8f4ff; /* Emphasized text — near-white */ --text-dim: #4a6a8a; /* Dimmed text — labels, captions */ /* ── Glow Effects (CSS box-shadow values) ── */ --glow-c: 0 0 18px rgba(0,220,255,0.35); /* Cyan glow */ --glow-g: 0 0 18px rgba(0,255,136,0.4); /* Green glow */ --glow-r: 0 0 18px rgba(255,56,96,0.4); /* Red glow */ --glow-a: 0 0 18px rgba(255,183,0,0.4); /* Amber glow */ }
--bgThe darkest color — the page background. The hex code #060912 is not pure black; it has a tiny amount of blue mixed in to feel like a dark computer screen.
rgba(..., 0.18)RGBA means Red, Green, Blue, Alpha. The fourth number (0.18) is opacity — 0 = invisible, 1 = solid. This gives semi-transparent borders that feel like a glowing edge, not a solid wall.
--glow-cThis is a box-shadow value, not a color. It creates the glowing halo effect around buttons. The 0 0 18px means: 0 horizontal offset, 0 vertical offset, 18px blur radius.

Code Education: Screen Architecture
How four screens work in one HTML page

The entire game lives on one HTML page, but users see it as four different "screens." This works because of a CSS rule that hides all screens by default, and JavaScript that adds the .active class to whichever screen should be visible.

CSS — The Screen Visibility Rules CSS
/* All screens are hidden by default */ .screen { display: none; } /* The .active screen is shown with a fade-slide animation */ .screen.active { display: flex; flex-direction: column; animation: screenIn 0.38s ease; } /* Animation: fade in from 18px below */ @keyframes screenIn { from { opacity: 0; transform: translateY(18px); } to { opacity: 1; transform: translateY(0); } }
JavaScript — showScreen() Function JavaScript
function showScreen(name) { // Step 1: Remove .active from ALL screens (hide everything) document.querySelectorAll('.screen').forEach(s => s.classList.remove('active')); // Step 2: Find the screen whose id matches 'screen-' + the name we want const el = document.getElementById('screen-' + name); if (!el) return; // Step 3: Force the animation to restart (trick: remove, reflow, restore) el.style.animation = ''; el.offsetHeight; // ← accessing offsetHeight forces browser to "re-read" the layout el.style.animation = ''; // Step 4: Add .active to show this screen el.classList.add('active'); // Step 5: Show/hide the floating restart button document.getElementById('fab-reset').style.display = (name === 'question') ? 'block' : 'none'; }
querySelectorAll('.screen')Returns ALL elements with the class "screen" as a list. Then .forEach() loops through each one and removes the .active class — hiding them all.
getElementById('screen-' + name)Builds the element ID by combining "screen-" with the name argument. So showScreen('splash') looks for the element with id screen-splash.
el.offsetHeightThis is a browser quirk: reading offsetHeight forces the browser to re-calculate the page layout, which allows CSS animations to restart correctly.
? 'block' : 'none'This is a ternary operator — a shorthand for if/else. It means: "if name equals 'question', use 'block'; otherwise use 'none'."

Code Education: The QUESTIONS Array
An array of objects — the game's data structure

The QUESTIONS constant is an array of objects. Each object represents one room. This is the most important data structure in the file — everything the game displays and checks comes from reading this array.

How Questions are Read and Displayed JavaScript
function showQuestion(idx) { S.currentQ = idx; // Save which question we're on S.wrongAttempts = 0; // Reset wrong guesses to 0 const q = QUESTIONS[idx]; // Get the question object at index idx // Update counter display: "1 / 20", "2 / 20", etc. document.getElementById('q-count').textContent = (idx + 1) + ' / ' + QUESTIONS.length; // Show room badge: "Room 3 — Boolean Bay" document.getElementById('room-badge').textContent = 'Room ' + (idx + 1) + ' — ' + q.room; // Display the question text document.getElementById('q-text').textContent = q.question; // Build choice buttons dynamically const cont = document.getElementById('choices'); cont.innerHTML = ''; // Clear any previous buttons const LETTERS = ['A','B','C','D','E']; q.choices.forEach((choice, i) => { // Loop through each choice const btn = document.createElement('button'); // Create a new button element btn.className = 'choice-btn'; btn.id = 'c' + i; // ID: c0, c1, c2, c3 btn.innerHTML = '<span class="letter">' + LETTERS[i] + '</span><span>' + choice + '</span>'; btn.onclick = () => pick(i); // When clicked, call pick() with this index cont.appendChild(btn); // Add button to the page }); }
QUESTIONS[idx]Square bracket notation reads one item from an array by its position number (index). QUESTIONS[0] is the first question, QUESTIONS[19] is the last of 20.
QUESTIONS.length.length is a built-in array property that returns how many items are in it. If there are 20 questions, QUESTIONS.length equals 20. This means the counter label "1 / 20" works even if the teacher changes to 15 or 25 questions.
q.choices.forEach()Loops through each answer choice string in the choices array for this question. The arrow function receives each item as choice and its position as i.
document.createElement('button')Creates a brand-new HTML button element in memory. It doesn't appear on screen until you use appendChild() to add it to an existing element.
btn.onclick = () => pick(i)Attaches a click event handler. The arrow function () => pick(i) means "when this button is clicked, call the pick() function with this choice's index number."

Code Education: State Management
How the game remembers what's happening

The let S = {...} object is the "state" — a snapshot of everything happening in the game at any given moment. Every meaningful piece of information is stored here, and every function reads from or writes to this object. It's the source of truth.

The Complete State Object JavaScript
let S = { phase: 'splash', // Which screen: 'splash' | 'codename' | 'question' | 'results' codename: '', // The student's chosen agent name currentQ: 0, // Index of the current question (0–19 for 20 questions) results: Array(QUESTIONS.length).fill(null), // null | 'correct' | 'skipped' per question firstTry: Array(QUESTIONS.length).fill(null), // null | true | false per question wrongAttempts: 0, // Wrong guesses on the CURRENT question startTime: null, // Date.now() timestamp when mission started endTime: null // Date.now() timestamp when results screen shown };
Array(20).fill(null)Creates an array of exactly 20 items, all set to null. This pre-allocates space for tracking each question's result before any answers are given.
results[idx] = 'correct'When a question is answered correctly, the results array at that position changes from null to the string 'correct'. This is how the progress bar and results grid know what to show.
wrongAttemptsResets to 0 every time a new question is loaded. Increments by 1 on every wrong guess. When it reaches 2, the Skip button appears.
startTime / endTimeDate.now() returns the current time in milliseconds since January 1, 1970. Subtracting startTime from endTime gives total elapsed milliseconds, which fmtTime() converts to "2m 34s" format.

Code Education: Core Functions
pick(), onCorrect(), onWrong(), skipQ() — the game logic

pick() — The Answer Handler

pick() — Called When a Student Clicks Any Choice JavaScript
function pick(choiceIdx) { const q = QUESTIONS[S.currentQ]; // Get the current question const btns = document.querySelectorAll('.choice-btn'); // Immediately disable ALL buttons (prevents double-clicking) btns.forEach(b => { b.disabled = true; }); // Was the clicked choice the correct answer? if (choiceIdx === q.answer) { onCorrect(choiceIdx); // Yes → celebrate and advance } else { onWrong(choiceIdx, btns); // No → show hint, re-enable choices } }

The key insight here: choiceIdx === q.answer uses triple-equals (strict equality) to compare the index of the button clicked against the answer number stored in the question object. If they match, the student chose correctly.

onCorrect() and onWrong()

onCorrect() — Celebrate and Advance JavaScript
function onCorrect(ci) { const idx = S.currentQ; S.results[idx] = 'correct'; // Record this question as correct S.firstTry[idx] = (S.wrongAttempts === 0); // Was it first try? true/false document.getElementById('c' + ci).classList.add('correct'); // Green highlight document.getElementById('ok-box').className = 'fb fb-ok show'; // Show ✓ banner document.getElementById('seg' + idx).className = 'p-seg unlocked'; // Green bar // Flash the whole screen green briefly const fl = document.getElementById('flash'); fl.classList.add('on'); setTimeout(() => fl.classList.remove('on'), 280); saveState(); // Persist to localStorage immediately // After 1.55 seconds, go to next question or show results setTimeout(() => { const next = idx + 1; if (next < QUESTIONS.length) showQuestion(next); else showResults(); }, 1550); }
onWrong() — Give Feedback and Re-Enable JavaScript
function onWrong(ci, btns) { S.wrongAttempts++; // Count this wrong attempt document.getElementById('c' + ci).classList.add('wrong'); // Red shake animation // Show the hint with a 💡 prefix const hb = document.getElementById('hint-box'); hb.textContent = '💡 Hint: ' + QUESTIONS[S.currentQ].hint; hb.className = 'fb fb-hint show'; // After 480ms: re-enable buttons and clear the red color setTimeout(() => { btns.forEach(b => { b.disabled = false; b.classList.remove('wrong'); }); }, 480); // If 2+ wrong guesses on this question, reveal the Skip button if (S.wrongAttempts >= 2) { document.getElementById('skip-btn').style.display = 'block'; } }

S.wrongAttempts++The ++ operator increments a number by 1. This is shorthand for S.wrongAttempts = S.wrongAttempts + 1.
S.wrongAttempts >= 2>= means "greater than or equal to." The Skip button only appears when a student has missed a question at least twice — giving them a chance to figure it out first.

Code Education: localStorage
How progress is saved between page refreshes

The browser has a built-in storage system called localStorage that lets a web page save data that persists even after the tab is closed. The escape room uses this to let students resume where they left off, even days later on the same computer.

The Three Storage Functions JavaScript
// ── SAVE: Convert the state object to a string and store it ── function saveState() { try { localStorage.setItem(CONFIG.storageKey, JSON.stringify(S)); } catch(e) {} // Silent fail (some browsers block localStorage) } // ── LOAD: Read the string back and convert it to an object ── function loadState() { try { const r = localStorage.getItem(CONFIG.storageKey); return r ? JSON.parse(r) : null; // If r exists, parse it; else return null } catch(e) { return null; } } // ── CLEAR: Delete the saved data (used on Restart) ── function clearState() { try { localStorage.removeItem(CONFIG.storageKey); } catch(e) {} }
JSON.stringify(S)JavaScript objects can't be stored directly — they must be converted to a text string first. JSON.stringify() converts the entire state object into a JSON string like '{"phase":"question","currentQ":5,...}'.
localStorage.setItem(key, value)Stores a string in the browser under the given key. Each student (each different storageKey in CONFIG) gets their own separate saved data slot.
JSON.parse(r)The reverse of stringify — converts the JSON text string back into a real JavaScript object that the code can use.
r ? ... : nullTernary: "if r has a value (is not null/empty), parse and return it; otherwise return null." This handles the case where no saved data exists yet (brand new player).
try { } catch(e) { }A try/catch block prevents the game from crashing if localStorage is blocked (some school networks or incognito modes disable it). The code tries the operation; if it fails for any reason, it silently moves on.
